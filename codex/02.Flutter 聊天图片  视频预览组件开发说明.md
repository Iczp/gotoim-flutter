# Flutter 聊天图片 / 视频预览组件开发说明

## 1. 目标

为聊天消息实现统一的媒体预览能力，主要支持：

- 图片消息预览
- 视频消息预览
- `Hero` 共享元素过渡动画
- 图片缩放
- 左右切换上一条 / 下一条媒体
- 下拉关闭预览
- 视频播放
- 图片 / 视频统一预览入口
- 支持本地文件和网络文件
- 支持 Android、iOS、Windows、macOS、Web

不要分别实现互不关联的：

- `ImagePreviewPage`
- `VideoPreviewPage`

应统一封装为媒体预览模块。

------

# 2. 开发原则

## 2.1 根据现有项目结构落地

先检查当前项目已有：

- Chat 模块
- Message Widget
- 图片消息组件
- 视频消息组件
- 路由体系
- 视频播放器
- 图片缓存组件
- 文件 / 附件模型
- Media / Attachment 相关模块

在现有结构中扩展。

不要为了本功能重新建立一套与现有项目重复的：

- Message 模型
- Attachment 模型
- 路由框架
- 网络图片封装
- 视频播放器封装

目录名称根据当前项目实际情况调整。

------

## 2.2 预览器与聊天消息模型解耦

预览组件不要直接依赖：

```dart
MessageEntity
```

或者具体聊天消息 DTO。

定义独立的预览模型，例如：

```dart
class MediaPreviewItem {
  final String id;
  final String messageId;

  final MediaPreviewType type;

  /// 原始图片 / 视频地址
  final String source;

  /// 缩略图
  final String? thumbnail;

  final int? width;
  final int? height;

  final Duration? duration;

  /// Hero 唯一标识
  final Object heroTag;

  const MediaPreviewItem({
    required this.id,
    required this.messageId,
    required this.type,
    required this.source,
    required this.heroTag,
    this.thumbnail,
    this.width,
    this.height,
    this.duration,
  });
}
```

类型：

```dart
enum MediaPreviewType {
  image,
  video,
}
```

聊天模块负责：

```text
Message
   ↓
Attachment
   ↓
MediaPreviewItem
   ↓
MediaPreview.open(...)
```

------

# 3. 对外 API

业务层调用尽量简单。

例如：

```dart
MediaPreview.open(
  context,
  items: items,
  initialIndex: index,
);
```

或者支持：

```dart
MediaPreview.open(
  context,
  items: items,
  initialId: attachment.id,
);
```

推荐最终提供：

```dart
abstract final class MediaPreview {
  static Future<void> open(
    BuildContext context, {
    required List<MediaPreviewItem> items,
    int initialIndex = 0,
  });
}
```

聊天图片和视频消息不应该关心：

- PageView
- Hero 动画
- 视频播放器生命周期
- 图片缩放
- 下拉关闭
- 状态栏
- 背景透明度
- 页面手势

这些都由媒体预览模块处理。

------

# 4. Hero 设计

## 4.1 Hero Tag 必须稳定

不要使用：

```dart
Hero(
  tag: index,
)
```

因为聊天消息：

- 会插入
- 会删除
- 会分页
- index 会发生变化

推荐：

```dart
String buildMediaHeroTag({
  required String messageId,
  required String mediaId,
}) {
  return 'chat-media-$messageId-$mediaId';
}
```

也可以结合当前项目现有 Message ID / Attachment ID。

要求：

```text
同一页面中的 Hero Tag 必须唯一。
```

------

# 5. 聊天图片消息

聊天列表中的图片组件只负责：

1. 显示缩略图
2. 提供 Hero 起点
3. 点击打开媒体预览

示例：

```dart
GestureDetector(
  onTap: () {
    MediaPreview.open(
      context,
      items: previewItems,
      initialIndex: currentIndex,
    );
  },
  child: Hero(
    tag: item.heroTag,
    transitionOnUserGestures: true,
    child: ChatImage(...),
  ),
)
```

注意：

`Hero` 内只包含主要视觉媒体内容。

不要把下面这些一起放进 Hero：

- 消息发送状态
- 消息时间
- 已读状态
- 下载进度
- 消息菜单
- 消息气泡
- 视频播放按钮
- 视频时长

------

# 6. 图片全屏预览

图片预览至少支持：

- 等比完整显示
- 双指缩放
- 拖动图片
- 双击放大 / 恢复
- 左右翻页
- Hero 返回
- 下拉关闭

图片可以使用：

```dart
InteractiveViewer
```

或者项目已有的图片缩放库。

如果使用第三方库，应检查当前项目依赖，避免重复引入功能类似的库。

------

# 7. 缩略图与原图

聊天页面通常显示缩略图：

```text
thumbnail
```

全屏页面显示：

```text
original image
```

但是 Hero 动画过程中不要突然把缩略图切换成原图。

推荐流程：

```text
聊天缩略图
     ↓
Hero 动画
     ↓
全屏缩略图
     ↓
加载原图
     ↓
原图淡入
```

避免：

```text
Hero 过程中：
缩略图 → 网络原图 → loading → 原图
```

导致：

- 闪白
- 图片尺寸跳变
- Hero 动画抖动

------

# 8. 视频 Hero

视频消息不能简单地把真实视频播放器直接作为 Hero。

聊天页面建议结构：

```text
┌─────────────────┐
│                 │
│   视频 Thumbnail │
│        ▶        │
│           01:25 │
└─────────────────┘
```

Hero 只包含：

```text
视频 Thumbnail
```

不要让真正的视频播放器参与 Hero 动画。

------

# 9. 视频打开流程

推荐：

```text
聊天视频封面
      ↓
     Hero
      ↓
全屏视频封面
      ↓
Hero 动画结束
      ↓
初始化播放器
      ↓
视频播放器 Fade In
```

即：

```text
Thumbnail
    ↓
Hero
    ↓
Thumbnail
    ↓
Video Player
```

这样可以减少：

- Hero 黑屏
- Texture 跳变
- SurfaceView 闪烁
- 播放器重新挂载问题

------

# 10. 视频播放器

如果当前项目已经存在统一视频播放器：

```text
优先复用。
```

不要在预览模块重新直接创建另一套播放器方案。

如果当前项目还没有跨平台视频播放器，则预留统一接口，例如：

```dart
class AppVideoPlayer extends StatefulWidget {
  final String source;
  final bool autoPlay;
  final bool showControls;
}
```

聊天模块和媒体预览模块统一通过：

```text
AppVideoPlayer
```

使用视频能力。

由于项目需要：

- Android
- iOS
- Windows
- macOS
- Web

底层播放器必须考虑完整跨平台支持。

播放器实现层可以使用 `media_kit`，但业务代码不要直接到处依赖 `media_kit` API。

------

# 11. PageView 媒体浏览

媒体预览页面使用：

```dart
PageView
```

例如：

```dart
PageView.builder(
  controller: pageController,
  itemCount: items.length,
  itemBuilder: (context, index) {
    final item = items[index];

    return switch (item.type) {
      MediaPreviewType.image =>
        MediaPreviewImage(item: item),

      MediaPreviewType.video =>
        MediaPreviewVideo(item: item),
    };
  },
)
```

支持混合：

```text
图片
图片
视频
图片
视频
图片
```

不要限制成：

```text
图片只能看图片
视频只能看视频
```

------

# 12. 当前页 Hero

需要注意：

PageView 内并不是所有媒体都需要同时激活 Hero。

特别是多个页面 Hero tag 和聊天页面对应时，要避免 Flutter Hero 冲突。

应保证：

```text
当前显示媒体
    ↓
对应聊天中的同一个 Hero
```

并检查页面切换过程中 Hero 是否有重复注册问题。

必要时可以：

```dart
HeroMode(
  enabled: isCurrentPage,
  child: ...
)
```

------

# 13. 图片缩放与 PageView 手势冲突

这是必须处理的问题。

默认：

```text
图片 Scale = 1
```

此时：

```text
左右滑动
    ↓
切换 PageView
```

图片放大：

```text
Scale > 1
```

此时：

```text
左右滑动
    ↓
移动图片
```

而不是直接切换下一张。

图片组件需要向外暴露：

```dart
onZoomChanged(bool isZoomed)
```

或者：

```dart
ValueNotifier<bool> zoomed
```

PageView 根据当前状态切换：

```dart
physics: zoomed
    ? const NeverScrollableScrollPhysics()
    : const PageScrollPhysics(),
```

如果使用的图片预览库本身已经解决 PageView 与 Zoom 手势竞争，则优先使用其机制。

------

# 14. 下拉关闭

实现类似主流 IM 的手势：

```text
全屏图片
    ↓

向下拖动

    ↓

媒体跟随手指移动

    ↓

背景逐渐透明

    ↓

媒体略微缩小

    ↓

超过阈值后关闭页面

    ↓

Hero 回到聊天消息
```

------

# 15. 下拉关闭状态

建议维护：

```dart
double dragOffsetY;
double dismissProgress;
```

计算：

```dart
final progress =
    (dragOffsetY.abs() / dismissThreshold)
        .clamp(0.0, 1.0);
```

背景透明度：

```dart
backgroundOpacity = 1 - progress;
```

媒体缩放：

```dart
scale = 1 - progress * 0.15;
```

媒体位移：

```dart
Transform.translate(
  offset: Offset(0, dragOffsetY),
)
```

------

# 16. 关闭阈值

例如：

```text
拖动超过一定距离
```

或者：

```text
拖动速度超过阈值
```

执行：

```dart
Navigator.pop(context);
```

否则：

```text
弹回原位置
```

动画参数不要写死散落在代码里。

统一定义配置，例如：

```dart
class MediaPreviewConfig {
  final double dismissDistance;
  final double maxDismissScale;
  final Duration animationDuration;
}
```

------

# 17. 图片放大时禁止下拉关闭

当：

```text
image scale > 1
```

不应该触发页面下拉关闭。

此时优先响应：

```text
图片内部 Pan / Zoom
```

只有：

```text
scale == 1
```

才允许：

```text
Swipe Down To Dismiss
```

避免手势冲突。

------

# 18. 视频播放状态

切换 PageView 时：

当前视频：

```text
播放
```

滑到其他媒体：

```text
暂停原视频
```

新的页面如果是视频：

```text
不要默认同时播放多个视频
```

建议：

```text
只允许当前 Page 的播放器活跃。
```

离开预览页面时：

```text
释放播放器资源。
```

```text
黑色背景
```

# 22. 视频 Controls

视频控制栏至少考虑：

- 播放 / 暂停
- 当前时间
- 总时长
- 拖动进度
- 静音
- 全屏状态

由于当前页面本身已经是媒体全屏页：

不要再次套一层播放器自己的“全屏 Route”。

播放器全屏按钮可以：

```text
隐藏
```

或者变成：

```text
横屏 / 竖屏切换
```

------

# 23. 屏幕方向

视频允许根据项目需求：

```text
竖屏播放
横屏播放
```

如果以后加入自动旋转：

```text
Video width > height
    ↓
可选择横屏
```

本次封装时不要把：

```text
SystemChrome.setPreferredOrientations
```

散落在业务代码。

如需要，由媒体预览控制器统一管理。

退出预览时必须恢复原来的方向策略。

# 24. System UI

媒体预览打开时可：

```text
隐藏部分系统 UI
```

不要影响整个 APP 后续页面。

系统状态恢复必须考虑：

```text

下拉关闭
系统返回按钮
路由被替换
异常 Dispose
```

# 28. Chat 媒体集合来源

点击一条聊天图片 / 视频时，预览列表应能够：

```text
查看当前聊天会话中的其他媒体。
```

例如：

```text
Message 1 图片
Message 2 文本
Message 3 图片
Message 4 视频
Message 5 文件
Message 6 图片
```

预览列表：

```text
图片
图片
视频
图片
```

文本和普通文件不进入本媒体预览列表。

------

# 29. 不要求一次加载整个聊天历史

聊天记录可能非常多：

```text
数万 / 数十万消息
```

媒体预览不能要求：

```text
打开页面前加载该会话全部图片视频。
```

本次结构要支持以后扩展：

```text
向前加载媒体
向后加载媒体
```

例如：

```dart
MediaPreviewDataSource
```

后续可以支持：

```dart
loadPrevious()
loadNext()
```

本次如果项目暂时没有媒体查询接口，可以先使用当前已经加载到本地的媒体消息。

但是架构不要写死成只能传完整 List。

------

# 30. Hero 与虚拟聊天列表

当前聊天列表可能是：

```text
Virtual List
Reverse List
Lazy Build
```

Hero 返回时，原消息 Widget 有可能已经离开 Widget Tree。

必须测试：

```text
点击图片
进入预览
左右查看很多媒体
返回
```

如果原 Hero 已被虚拟列表回收：

不能让页面崩溃。

Flutter Hero 找不到 destination 时应允许正常关闭，而不是让业务逻辑依赖 Hero 一定存在。

后续可以扩展：

```text
返回前滚动聊天列表定位原消息
```

但不是本次第一阶段必须实现的功能。

------

# 31. Hero 动画形状

聊天图片可能具有：

```text
圆角
聊天气泡 ClipPath
特殊气泡尾巴
```

而全屏媒体通常是：

```text
无圆角
```

Hero 飞行动画期间建议让：

```text
BorderRadius
```

逐渐：

```text
8 -> 0
```

如果当前聊天媒体已经经过：

```text
聊天气泡 ClipPath
```

不要直接让复杂 `CustomClipper` 在全屏 Hero 中持续参与动画。

推荐 Hero 的视觉层单独处理。

------

# 32. 图片尺寸

聊天中的图片可能是：

```text
100 × 300
300 × 100
400 × 400
```

Hero 进入全屏时应正确：

```text
BoxFit.cover
      ↓
BoxFit.contain
```

注意该变化很容易产生视觉跳变。

建议 Hero Flight 中使用：

```text
统一的 Media Hero Widget
```

并通过：

```dart
flightShuttleBuilder
```

必要时自定义过渡。

# 36. 生命周期

重点测试：

```text
打开图片

关闭
```

# 39. 错误处理

不能因为一个媒体加载失败导致整个 PageView 异常。

例如：

```text
第 3 张图片失效
```

用户仍然应该可以：

```text
滑到第 2 张
滑到第 4 张
返回聊天
```

视频错误同理。

# 48. 验收标准

最终聊天中的使用应足够简单：

```dart
onTap: () {
  MediaPreview.open(
    context,
    items: mediaItems,
    initialIndex: currentIndex,
  );
}
```

图片：

```text
聊天缩略图
  ↓ Hero
全屏缩略图
  ↓
高清原图
```

视频：

```text
聊天视频封面
  ↓ Hero
全屏视频封面
  ↓
Video Player
```

用户能够：

```text
点击打开
左右浏览
缩放图片
播放视频
下拉关闭
Hero 返回
```

同时：

```text
图片 / 视频预览逻辑统一
聊天模块保持轻量
播放器生命周期正确
多平台行为一致
后续可以继续增加保存、转发、分享等功能
```
