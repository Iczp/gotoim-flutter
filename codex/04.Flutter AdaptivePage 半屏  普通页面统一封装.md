# Flutter AdaptivePage 半屏 / 普通页面统一封装

## 一、目标

实现统一的 `AdaptivePage` 页面容器，用于 Flutter 项目中的半屏页面。

半屏页面不能简单理解为普通页面缩小版。

需要支持：

- 半屏只展示精简内容。
- 转普通页面后展示完整内容。
- 半屏和普通页面共用业务数据和状态。
- 部分半屏允许转普通页面。
- 部分半屏禁止转普通页面。
- 支持软键盘。
- 支持内容自适应高度。
- 支持可拖拽半屏。
- 支持 Android、iOS、Windows、macOS，Web 尽量兼容。

------

## 二、核心 API

统一入口：

```dart
AdaptivePage.open(...)
```

直接打开普通页面：

```dart
AdaptivePage.push(...)
```

页面 Controller：

```dart
controller.isCompact
controller.isFull

controller.canConvertToPage

controller.toPage()

controller.expandSheet()
controller.collapseSheet()

controller.close()
```

------

## 三、转换普通页面开关

必须提供：

```dart
canConvertToPage
```

例如：

```dart
const AdaptivePageConfig(
  canConvertToPage: true,
)
```

表示：

```text
半屏
↓
允许
↓
普通完整页面
```

如果：

```dart
canConvertToPage: false
```

则：

- 不显示“打开完整页面”按钮。
- `controller.canConvertToPage == false`。
- 调用 `controller.toPage()` 不产生任何操作。
- 页面只能作为半屏使用。

不要让业务页面自己实现这一套判断。

------

## 四、页面展示状态

统一定义：

```dart
enum AdaptivePagePresentation {
  compact,
  full,
}
```

其中：

```text
compact
=
半屏精简模式

full
=
普通页面完整模式
```

业务 Widget 根据状态控制内容。

例如：

```dart
if (controller.isFull) {
  // 完整内容
}
```

半屏专属内容：

```dart
if (controller.isCompact) {
  // 半屏内容
}
```

------

## 五、设计原则

不要分别实现：

```text
UserProfileSheet
UserProfilePage
```

然后维护两套业务代码。

优先设计：

```text
UserProfileController
        ↓
UserProfileView
        ↓
AdaptivePagePresentation
        ↓
compact / full
```

共用：

- API 数据
- Controller
- Form 数据
- 页面状态
- 公共 Widget

仅根据 Presentation 调整 UI。

------

## 六、半屏与完整页允许内容不同

例如用户资料。

### 半屏 compact

只显示：

- 头像
- 昵称
- 在线状态
- 发消息
- 视频通话
- 查看完整资料

### 普通页 full

继续显示：

- 账号
- 地区
- 个性签名
- 标签
- 共同群聊
- 权限
- 更多资料

不要要求半屏把完整页面的所有内容都渲染出来。

------

## 七、半屏高度模式

支持：

```dart
enum AdaptiveSheetSizingMode {
  content,
  draggable,
}
```

### content

内容较少时：

```text
内容多高
↓
Sheet 多高
```

但是最高不能超过：

```dart
maxContentHeightFactor
```

例如：

```dart
maxContentHeightFactor: 0.75
```

表示最高占屏幕 75%。

适用于：

- 用户摘要
- 消息操作
- 快捷信息
- 简单表单

------

### draggable

支持：

```dart
initialSize
minSize
maxSize
```

例如：

```dart
initialSize: 0.6,
minSize: 0.4,
maxSize: 0.95,
```

适用于：

- 搜索
- 联系人列表
- 文件列表
- 地图附近位置
- 长列表

------

## 八、DraggableScrollableSheet 规范

如果使用：

```dart
AdaptiveSheetSizingMode.draggable
```

内部主 ListView / CustomScrollView 必须优先使用：

```dart
controller.scrollController
```

例如：

```dart
ListView.builder(
  controller: controller.scrollController,
)
```

避免：

```text
ListView 滚动
和
Sheet 拖动
```

互相抢手势。

------

## 九、键盘处理

必须：

```dart
showModalBottomSheet(
  isScrollControlled: true,
)
```

使用：

```dart
MediaQuery.viewInsetsOf(context).bottom
```

监听软键盘。

但是键盘 Padding 只能应用到：

```text
Sheet Body
```

不要应用到整个 Sheet。

正确结构：

```text
Sheet
├── DragHandle
├── Header
└── KeyboardAwareBody
```

不要：

```text
KeyboardPadding
└── 整个 Sheet
```

否则键盘出现时 Header 和整个 Sheet 会明显跳动。

键盘 Padding 使用动画：

```dart
AnimatedPadding
```

默认约：

```text
180ms
```

------

## 十、普通页面键盘

普通页面使用：

```dart
Scaffold(
  resizeToAvoidBottomInset: true,
)
```

不要再额外增加相同的 `viewInsets.bottom` Padding，防止重复避让键盘。

------

## 十一、半屏转普通页面

调用：

```dart
controller.toPage()
```

逻辑：

```text
关闭键盘
↓
关闭当前 BottomSheet
↓
等待 BottomSheet Route 结束
↓
presentation = full
↓
Navigator.push 普通 PageRoute
```

不要简单把 BottomSheet 高度改成：

```text
100%
```

因为：

```text
Sheet 全屏
```

和：

```text
真正普通 PageRoute
```

是两个不同概念。

------

## 十二、业务状态

转普通页面时不能导致用户已经填写的数据丢失。

例如：

```text
半屏填写备注
↓
点击完整页面
↓
备注必须还在
```

业务状态不要只存在于 Sheet Widget 自己的临时 State 中。

优先：

```text
Controller
Riverpod
Bloc
Provider
或者现有项目状态方案
```

半屏和普通页面复用同一个状态实例。

------

## 十三、Header

半屏统一包含：

```text
拖拽 Handle

标题                    ⛶   ×
```

其中：

```text
⛶
```

只在：

```dart
canConvertToPage == true
```

时显示。

普通页面使用标准：

```text
← 标题
```

------

## 十四、业务页面使用示例

```dart
AdaptivePage.open(
  context,
  config: const AdaptivePageConfig(
    title: '用户资料',
    canConvertToPage: true,
    sheetSizingMode:
        AdaptiveSheetSizingMode.content,
  ),
  builder: (
    context,
    controller,
  ) {
    return UserProfileView(
      controller: controller,
    );
  },
);
```

业务页面：

```dart
if (controller.isCompact) {
  // 显示摘要
}

if (controller.isFull) {
  // 显示完整内容
}
```

## 十七、开发诊断中心

项目已有的“开发诊断中心”增加 AdaptivePage 演示入口。

至少提供以下人工测试案例：

### Case 1：短内容半屏

```text
content 模式
canConvertToPage = true
```

验证：

- 高度随内容。
- 可以进入完整页面。

### Case 2：禁止转换

```text
canConvertToPage = false
```

验证：

- 不显示全屏按钮。
- 无法进入普通页。

### Case 3：长列表

```text
draggable
```

验证：

- 可拖动。
- ListView 可正常滚动。
- 两种手势没有明显冲突。

### Case 4：输入框

半屏加入多个 TextField。

验证：

- 键盘弹出后输入框可见。
- Header 不发生异常跳动。
- 关闭键盘恢复正常。

### Case 5：半屏填写数据 → 普通页面

半屏填写：

```text
昵称
备注
搜索文字
```

再进入完整页面。

验证：

- 已填写内容不丢失。

### Case 6：系统返回键

分别验证：

```text
Android Back
iOS 返回
桌面端关闭
```

Route 行为正确。
