## 一、任务目标

在当前 Flutter 项目中实现统一的头像显示组件，并完成“选择头像 → 裁剪 → 上传 → 更新用户头像”的完整接入。

项目目录：

```text
F:\Dev\GotoIM\gotoim-flutter
```

不要修改旧 UniApp 项目。

本任务需要结合当前项目已经存在的：

```text
core/
data/
services/
features/user/
features/media/
features/setting/
```

以及现有：

```text

Dio

```

进行实现。

不要为了本任务重新创建一整套重复的：


实现前先搜索现有代码并复用。

# 三、头像形状设置

应用设置中存在：

```text
头像形状
```

支持：

```text
圆形
方形
```

定义统一枚举，例如：

```dart
enum AvatarShape {
  circle,
  square,
}
```

具体命名根据项目现有命名规范调整。

## 重要原则

这个设置只是：

```text
显示 / 预览效果
```

不是头像文件本身的属性。

不要保存：

```text
user.avatarShape
group.avatarShape
message.avatarShape
```

到每一个用户、群或消息对象。

头像形状属于统一的 UI 显示设置。

例如：

```text
设置 = circle

聊天消息头像     ○
会话列表头像     ○
联系人头像       ○
个人头像         ○
群头像           ○
```

切换：

```text
设置 = square

聊天消息头像     □
会话列表头像     □
联系人头像       □
个人头像         □
群头像           □
```

所有使用统一头像组件的地方自动变化。

# 九、头像形状来源

AppAvatar 应支持两种方式：

## 默认

跟随全局设置：

```dart
AppAvatar(...)
```

内部通过项目现有 Riverpod 设置体系得到：

```text
AvatarShape
```

## 显式覆盖

部分特殊 UI 允许：

```dart
AppAvatar(
  shape: AvatarShape.circle,
)
```

例如某些设计固定要求圆形。

因此 shape 概念上应类似：

```text
null
    ↓
跟随系统头像设置

circle / square
    ↓
强制使用指定形状
```

不要要求每个调用者都这样写：

```dart
final shape = ref.watch(settingsProvider...).avatarShape;

AppAvatar(
  shape: shape,
)
```

否则整个项目会产生大量重复代码。

优先让统一 Avatar 组件或者其包装层处理默认设置。

同时注意 Riverpod rebuild 粒度：

```text
只监听 avatarShape
```

不要因为 AvatarShape 改变而让头像组件监听整个巨大 Settings 对象。

# 十、方形头像

`AvatarShape.square` 是 UI 样式。

根据当前 GotoIM UI 设计，检查项目已有：

```text
BorderRadius
Design Token
Theme Extension
```

如果已有统一圆角尺寸，使用现有 Token。

不要到处写死：

```dart
BorderRadius.circular(8)
```

如果项目目前没有统一 Token，可以在 Avatar 组件内部设置合理默认值。

例如：

```text
circle
    100% 圆形

square
    方形 / 小圆角矩形
```

这里的“方形”并不代表头像图片文件必须处理成方形透明 PNG。

# 十一、头像文件统一保存为 1:1

无论用户设置：

```text
圆形
```

还是：

```text
方形
```

真正上传服务器的头像图片统一处理为：

```text
1:1
```

例如：

```text
512 × 512

或

1024 × 1024
```

不要：

```text
圆形设置
    ↓
生成透明圆形 PNG
```

也不要：

```text
圆形头像存一份
方形头像存一份
```

只保存标准的：

```text
1:1 正方形头像原图
```

圆形只是 UI Clip。

这样同一个头像文件可以：

```text
○ 圆形显示

□ 方形显示
```

# 十四、裁剪框只是预览

当：

```text

```

```text

```

让用户看到头像最终圆形展示时大概是什么效果。

当：

```text

```

```text

```

但是无论哪个模式：

```text

    ↓
1:1 正方形图片
```

即：

```text
圆形裁剪框
```

只是：

```text
视觉 Preview Mask
```

并不是要求最终生成圆形 Bitmap。

# 二十七、缓存问题

头像 URL 如果没有发生变化但服务器文件内容已经变化，需要注意：

```text

```

缓存不会自动知道服务器图片已经更新。

实现时检查后端是否：

```text

```

```text

```

如果 URL 固定：

```text

```

则需要结合当前图片缓存体系：

```text

或者

```

不要粗暴：

```text

```

因此需要注意：

```text
不要在 build 中解析复杂 URL
不要重复读取本地设置
不要重复创建大对象
不要每个头像单独请求 User API
不要使用过大的 decode 尺寸
```

网络图片如果现有图片组件支持：

```text
memCacheWidth
memCacheHeight
```

可以根据头像显示尺寸合理设置 decode size。

例如 40px Avatar 没必要在内存中长期解码 4000×4000 图片。

但要结合：

```text
devicePixelRatio
```

确保清晰度。

# 三十五、裁剪页无需监听设置动态变化

裁剪页打开时读取一次：

```text
avatarShape
```

即可。

例如：

```text
打开裁剪页时 = circle
```

即使理论上设置在其他窗口发生变化，也不需要裁剪页面实时：

```text
circle ↔ square
```

切换 Mask。

完成这次裁剪以后下一次打开再读取最新设置。

保持实现简单。
