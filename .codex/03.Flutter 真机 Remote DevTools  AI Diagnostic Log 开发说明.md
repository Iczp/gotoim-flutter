# Flutter 真机 Remote DevTools / AI Diagnostic Log 开发说明

## 1. 目标

为 Flutter 项目实现一套仅用于开发/测试环境的真机远程诊断工具。

真机运行 APP 后，在手机内部启动：

- HTTP Server
- WebSocket Server
- 日志采集系统
- 内存日志缓存
- 可选滚动文件日志
- Web Remote DevTools 页面

开发人员在电脑浏览器访问：

```text
http://<手机局域网IP>:18080
```

即可实时查看真机日志、搜索、暂停、复制、导出和定位异常。

本功能最终最重要的用途不是“方便人看日志”，而是：

> 将高质量、结构化、包含源码定位信息的诊断数据直接交给 Codex / AI，让 AI 能够读取项目源码并快速定位问题。

------

# 2. 核心原则

优先级：

```text
TraceId
>
源码文件 / 行号 / 函数
>
Error Stack
>
相关源码文件
>
异常前后事件
>
HTTP / SignalR / DB 上下文
>
Git 版本
>
设备运行环境
>
普通日志文本
```

设计原则：

```text
人负责复现问题
↓
系统负责完整收集证据
↓
AI 根据日志直接读取对应源码
↓
定位并修复问题
```

普通日志应尽量轻量。

ERROR / FATAL 日志需要自动补充更多诊断信息。

# 5. 日志统一入口

业务代码不得直接操作 Remote HTTP / WebSocket。

统一：

```dart
AppLogger.debug(...)
AppLogger.info(...)
AppLogger.warning(...)
AppLogger.error(...)
AppLogger.fatal(...)
```

例如：

```dart
AppLogger.info(
  'SignalR connected',
  category: 'signalr',
  event: 'signalr_connected',
);
```

异常：

```dart
AppLogger.error(
  'Send message failed',
  category: 'chat.message',
  event: 'send_message_failed',
  error: e,
  stackTrace: stackTrace,
);
```

Logger 内部再负责：

```text
Console
+
Memory RingBuffer
+
WebSocket
+
Optional File Log
```

# 7. SourceLocation

重点实现。

```dart
class SourceLocation {
  final String file;

  final int? line;

  final int? column;

  final String? function;
}
```

例如：

```json
{
  "file": "lib/features/chat/application/send_message_service.dart",
  "line": 182,
  "column": 17,
  "function": "SendMessageService.send"
}
```

## 文件路径规则

优先使用：

```text
项目相对路径
```

例如：

```text
lib/features/chat/application/send_message_service.dart
```

不要把：

```text
F:\Dev\GotoIM\gotoim_flutter\...
```

作为主要源码定位方式。

因为 Codex 通常已经位于项目根目录。

如果需要记录项目根路径，仅放入：

```text
manifest
environment
```

不要每条日志重复保存。

# 8. StackTrace 解析

Flutter 原始：

```text
#0 Foo.bar (package:gotoim/features/chat/foo.dart:123:19)
```

应解析成结构：

```json
{
  "index": 0,
  "file": "lib/features/chat/foo.dart",
  "line": 123,
  "column": 19,
  "function": "Foo.bar",
  "appCode": true
}
```

需要区分：

```text
Application Code
Package Code
Flutter Framework
Dart SDK
Native
```

AI 诊断时优先：

```text
Application Code
```

Web 端默认也优先展示业务代码 Stack Frame。

------

# 9. ERROR 自动识别源码位置

对于：

```text
ERROR
FATAL
```

如果调用方没有显式传入：

```text
source
```

Logger 应尽可能从 StackTrace 自动提取第一条业务代码 Frame。

例如：

```text
lib/features/chat/application/send_message_service.dart:182:17
```

最终输出：

```text
source.file
source.line
source.column
source.function
```

让 Codex 可以直接打开对应文件。

# 10. Related Files

日志支持：

```dart
relatedFiles
```

例如认证问题：

```json
{
  "relatedFiles": [
    "lib/core/auth/token_manager.dart",
    "lib/core/network/interceptors/token_refresh_interceptor.dart",
    "lib/core/network/auth_dio.dart"
  ]
}
```

发送消息：

```json
{
  "relatedFiles": [
    "lib/features/chat/application/send_message_service.dart",
    "lib/features/chat/data/message_repository.dart",
    "lib/features/chat/data/message_local_store.dart"
  ]
}
```

这些文件用于告诉 AI：

```text
发生异常后优先检查哪些源码
```

不要自动把几十个文件全部加入。

通常：

```text
1～5 个
```

比较合理。

------

# 11. Diagnostic Hint

允许业务模块提供 AI 诊断提示。

例如：

```json
{
  "diagnostic": {
    "summary": "Request still returned HTTP 401 after token refresh",
    "suspectedArea": "authentication/token-refresh",
    "inspectReason": "The request was retried after token refresh but still failed."
  }
}
```

原则：

不要输出未经证实的：

```text
Bug 一定在 TokenManager
```

应该输出：

```text
事实
+
建议检查区域
```

AI 负责做最终判断。

# 12. TraceId

所有重要操作应支持 Trace。

重点包括：

```text

刷新 Token
发送消息
发送图片
文件上传
文件下载
SignalR 重连
数据库同步
WebView 页面加载
扫码登录
Native 调用
```

例如：

```text
traceId =
msg-send-01Kxxxx
```

贯穿：

```text
UI
↓
Controller
↓
Service
↓
Repository
↓
Dio
↓
HTTP
↓
Local DB
↓
SignalR
↓
UI State
```

示例：

```text
00:12:30.101 UI
send clicked

00:12:30.105 DB
pending message inserted

00:12:30.941 HTTP
POST /api/chat/message

00:12:31.320 HTTP
200

00:12:31.332 DB
updating pending message

00:12:31.382 ERROR
Null check operator used on a null value
```

AI 一眼即可判断：

```text
HTTP 已成功
问题发生在本地 ACK / 状态更新阶段
```

# 13. HTTP / Dio 日志

项目现有 Dio Client 应接入统一 Logger。

不要为了日志创建新的 HTTP 层。

至少记录：

```text
method
url
query
statusCode
duration
requestSize
responseSize
traceId
requestId
```

ERROR / 慢请求可增加：

```text
caller
调用源码文件
line
function
```

例如：

```text
POST /api/chat/message

source:
lib/features/chat/data/message_remote_data_source.dart:83

calledBy:
lib/features/chat/application/send_message_service.dart:157
```

普通成功请求不必全部生成完整 StackTrace，避免性能浪费。

# 17. 内存日志

禁止无限增长。

使用 RingBuffer。

默认：

```text
最近 5000 条
```

例如：

```text
1
2
...
5000

新增第 5001 条
↓
自动移除第 1 条
```

保证真机长时间运行不会因为日志导致内存不断增长。

------

# 18. 文件日志

可选。

使用 Rolling File。

例如：

```text
5 MB / 文件
最多 5 个
```

总容量约：

```text
25 MB
```

超过后自动覆盖最老文件。

不要无限保存。


# 22. Pause 语义

必须区分：

## Pause View

仅暂停 Web 页面刷新。

手机仍正常收集日志。

暂停期间：

```text
WebSocket
↓
Browser Buffer
```

Resume 后批量追加。

## Stop Capture

真正通知 Flutter 暂停日志采集。

两者不要设计成同一个按钮。

------

# 23. Clear 语义

区分：

```text
Clear View
```

只清浏览器当前数据。

以及：

```text
Clear Server
```

清手机端 RingBuffer / 当前日志缓存。

避免误操作直接删除诊断证据。

# 24. 大量日志性能

Web 页面必须考虑：

```text
1 万
5 万
10 万+
```

日志。

禁止无限创建 DOM。

必须使用：

```text
Virtual List
```

日志主列表尽量采用：

```text
固定行高
```

```text
右侧 Detail Panel
```

不要通过在列表内部展开大 JSON 形成大量可变高度节点。

# 37. logs.jsonl

大量日志不要保存成一个巨大的 JSON Array。

建议：

```text
JSON Lines
```

即：

```json
{"id":"1","level":"info",...}
{"id":"2","level":"debug",...}
{"id":"3","level":"error",...}
```

优点：

```text
流式写入

大文件处理方便

AI / 脚本容易分段读取

不需要整个文件一次性解析
```

```json
    "mode": "debug",
    "flutter": "...",
```

```text

```

```json

}
```

```text

```

# 45. 性能要求

日志系统本身不能成为 APP 卡顿原因。

必须考虑：

```text
高频 SignalR
大量 HTTP
大量 DB 操作
长时间运行
```

要求：

```text
RingBuffer
批量 WebSocket
批量 Web UI Render
Virtual List
限制 Payload 大小
限制文件大小
```

不要为每一条普通 DEBUG 日志：

```text
抓完整 StackTrace
读取 Git
读取设备信息
读取多个源码位置
```

这些应主要用于：

```text
ERROR
FATAL
慢请求
特殊诊断事件
```

------

# 46. 安全

Remote DevTools 默认：

```text
Release = Disabled
```

至少考虑：

```text
局域网暴露

敏感 HTTP Header

HTTP Body

Token

Cookie

密码

聊天内容
```

实现统一脱敏。

不要因为诊断工具把用户敏感数据完整保存到：

```text
日志
Web UI
Diagnostic Bundle
```

# 50. 最终验收标准

出现一个 Flutter 真机问题后，开发人员应该能够：

```text
1. 打开电脑浏览器 Remote DevTools

2. Clear / Start Snapshot

3. 在真机复现问题

4. Pause View

5. 找到 Error

6. 查看完整 Trace

7. 点击 Copy for AI
   或 Export Diagnostic Bundle

8. 将结果交给 Codex

9. Codex 根据日志中的：
   文件名
   行号
   函数
   Trace
   Related Files

   直接读取当前项目源码

10. 定位问题并修改代码
```

如果还需要开发人员手工告诉 AI：

```text
这个错误大概在哪个模块

你去找一下哪个文件

我记得可能是这里
```

说明这套诊断日志还没有达到目标。

最终要求：

> 日志本身就是一份可以直接交给 Codex 的 Bug Investigation Context。
