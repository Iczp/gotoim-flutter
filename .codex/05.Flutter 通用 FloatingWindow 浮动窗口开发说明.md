# Flutter 通用 FloatingWindow 浮动窗口开发说明

## 1. 目标

在当前 Flutter 项目中实现一套项目级通用 `FloatingWindow` 浮动窗口能力。

它不是单独的视频小窗组件，而是能够承载任意业务内容的 App 内浮窗系统。

主要场景：

```text
FloatingWindow
├── 视频播放
├── 视频通话
├── 语音通话
├── WebView / H5
├── 直播
├── 文件传输
├── AI 长任务
├── 地图
├── Camera Preview
└── 自定义 Widget
```

第一阶段重点保证：

- App 内自由拖动
- 左右自动吸边
- 跨 Flutter 路由持续存在
- SafeArea 避让
- 键盘避让
- 横竖屏变化
- 桌面窗口 Resize
- 多浮窗
- 层级管理
- Flutter Widget 支持
- WebView / PlatformView 支持
- 视频播放状态保持
- WebView 页面状态尽量保持
- Android / iOS / Windows / macOS
- Web 平台按能力兼容

本阶段不做系统级悬浮窗。

------

# 2. 核心设计原则

FloatingWindow 只负责“窗口”，不负责“业务”。

```text
FloatingWindow
负责：

位置
尺寸
拖动
吸边
层级
显示/隐藏
边界
SafeArea
Keyboard
窗口变化
```

业务自己负责：

```text
Video
WebView
Call
Map
Camera
Transfer
AI Task
```

禁止在通用 FloatingWindow 中直接依赖：

```text
Message
Chat
VideoPlayer
WebView Plugin
SignalR
LiveKit
业务 API
```

------

# 3. 使用范围

适合：

```text
离开当前页面后仍然需要继续存在的内容
```

例如：

### 视频

```text
聊天视频
↓
进入播放器
↓
缩小
↓
继续播放
↓
继续浏览聊天
```

### 视频通话

```text
通话中
↓
打开其他聊天
↓
通话缩成小窗
```

### WebView

```text
打开工作台 / H5 / 小程序
↓
缩成浮窗
↓
继续使用 Flutter 主界面
↓
点击恢复
```

### 文件任务

```text
发送大文件
↓
后台继续上传
↓
浮窗显示任务进度
```

# 4. 不适合 FloatingWindow 的场景

以下不要使用 FloatingWindow：

```text
聊天消息菜单
Tooltip
Toast
Emoji Popup
普通 Dialog
操作确认
普通 BottomSheet
```

这些仍使用：

```text
Overlay
Popup
Dialog
BottomSheet
```

判断原则：

> 用户离开当前页面后，这个内容是否还应该继续存在？

如果是，才考虑 FloatingWindow。

------

# 5. 与 Hero 的关系

Hero 和 FloatingWindow 不是同一种能力。

聊天视频建议：

```text
聊天视频缩略图
        ↓
       Hero
        ↓
视频预览 / 播放页面
        ↓
点击缩小
        ↓
FloatingWindow
```

Hero：

```text
负责页面之间视觉转场
```

FloatingWindow：

```text
负责业务持续存在
```

不要用 Hero 来实现视频持续播放的小窗。

------

# 6. 与系统 PiP 的关系

本组件属于：

```text
App 内 FloatingWindow
```

不是：

```text
Android / iOS Picture-in-Picture
```

App 内：

- 可以自由拖动
- 自定义 UI
- 自定义大小
- 自定义按钮
- Flutter 页面之间继续存在

系统 PiP：

- App 后台仍可显示
- 位置由操作系统控制
- UI 受系统限制

未来架构：

```text
VideoPlaybackSession
        │
        ├── App FloatingWindow
        │
        └── System PiP
```

FloatingWindowManager 不直接实现 PiP。

# 8. 根节点架构

FloatingWindow 必须挂载在 App 根部。

例如：

```dart
MaterialApp(
  builder: (context, child) {
    return FloatingWindowScope(
      child: Stack(
        children: [
          child!,
          const FloatingWindowLayer(),
        ],
      ),
    );
  },
);
```

实际位置根据当前项目：

```text
MaterialApp
MaterialApp.router
Router
Navigator
ShellRoute
```

决定。

要求：

```text
切换页面
↓
FloatingWindowLayer 不销毁
```

禁止挂到：

```text
ChatPage
VideoPage
WorkbenchPage
```

等具体页面中。

# 9. FloatingWindowManager

提供统一管理入口。

建议：

```dart
class FloatingWindowManager {
  void show(...);

  void hide(String id);

  void showWindow(String id);

  void close(String id);

  void closeAll();

  void bringToFront(String id);

  void updatePosition(
    String id,
    Offset position,
  );

  void updateSize(
    String id,
    Size size,
  );

  FloatingWindowEntry? find(String id);

  bool contains(String id);
}
```

优先使用项目当前已有状态管理方案。

不要为 FloatingWindow 单独引入新的大型状态管理框架。

Manager 尽量不要要求：

```dart
show(context, ...)
```

推荐：

```dart
show(...)
```

Manager 负责状态。

Layer 负责渲染。

# 10. FloatingWindowEntry

参考：

```dart
class FloatingWindowEntry {
  final String id;

  final FloatingWindowType type;

  final FloatingWindowContentMode contentMode;

  final Widget child;

  final FloatingWindowOptions options;

  final Offset position;

  final Size size;

  final bool visible;

  final int zIndex;

```

使用不可变数据。

提供：

```dart
copyWith()
```

增加：

```dart
enum FloatingWindowContentMode {
```

```text

```

例如：

```text

```

```text
platformView
```

例如：


- Clip
- Rebuild 优化

- 平台特殊处理

不要让 ContentMode 绑定某一个具体插件。

# 14. ID 规则

所有 FloatingWindow 必须有稳定 ID。

例如：

```text
video:{mediaId}

call:{callId}

webview:{instanceId}

transfer:{taskId}

custom:{id}
```

如果：

```dart
show(id: existingId)
```

默认：

```text
更新已有窗口
+
显示
+
bringToFront
```

不能重复创建同 ID 窗口。

------

# 15. 多浮窗

核心架构必须支持：

```text
FloatingWindowLayer
├── Window A
├── Window B
└── Window C
```

维护：

```text
zIndex
```

点击或操作窗口时：

```dart
bringToFront(id);
```

但业务可以自行限制：

```text
最多一个视频窗口
最多一个通话窗口
```

这种限制不能写死在通用组件中。

------

# 16. 拖动

支持：

- Touch
- Mouse
- Trackpad

实现：

```text
onPanStart
onPanUpdate
onPanEnd
```

拖动只移动 FloatingWindow 外层。

不要因为位置变化重新创建业务 Child。

------

# 17. PlatformView 拖动规则

WebView / Map / Camera 等内容与普通 Widget 不一样。

不能默认：

```text
整个窗口区域都可以拖
```

否则会与内部：

```text
网页滚动
网页点击
地图拖动
地图缩放
Camera 手势
```

冲突。

PlatformView 默认使用独立 DragRegion：

```text
┌───────────────────────────┐
│ ≡  页面标题            ×  │ ← DragRegion
├───────────────────────────┤
│                           │
│          WebView          │
│                           │
└───────────────────────────┘
```

即：

```dart
Column(
  children: [
    FloatingWindowDragRegion(
      child: Header(),
    ),
    Expanded(
      child: WebViewContent(),
    ),
  ],
)
```

WebView 内部正常：

- 点击
- 滚动
- 输入
- 长按
- JS 交互

Header 才负责窗口移动。

------

# 18. 边界计算

不能单纯：

```dart
MediaQuery.sizeOf(context)
```

需要计算：

```text
availableRect
```

综合：

```text
screen
-
SafeArea
-
Keyboard
-
FloatingWindow margin
```

需要使用：

```dart
MediaQuery.paddingOf(context)
MediaQuery.viewPaddingOf(context)
MediaQuery.viewInsetsOf(context)
```

窗口始终 Clamp 到合法区域。

------

# 19. Keyboard 避让

尤其聊天和 WebView 都会频繁输入。

当：

```dart
avoidKeyboard == true
```

键盘弹出：

```text
重新计算 availableRect
↓
当前 FloatingWindow 如果被覆盖
↓
移动到合法位置
```

键盘关闭后：

不要强制回到旧位置。

保留当前合法位置即可。

------

# 20. SafeArea

默认：

```dart
avoidSafeArea = true
```

处理：

- 刘海
- Dynamic Island
- 状态栏
- Android 手势区域
- iOS Home Indicator
- 桌面安全区域

特殊业务允许关闭。

------

# 21. 左右吸边

拖动结束：

```text
onPanEnd
↓
比较窗口中心离左右边缘距离
↓
选择最近边
↓
短动画吸附
```

只实现：

```text
左
右
```

第一阶段不做上下磁吸。

建议动画：

```text
150ms ~ 250ms
```

# 22. Resize

移动端默认：

```dart
resizable: false
```

桌面端可以：

```dart
resizable: true
```

支持：

```text
minSize
maxSize
aspectRatio
keepAspectRatio
```

视频：

```text
保持视频比例
```

WebView：

```text
通常不强制宽高比
```

Windows/macOS 可显示 Resize Handle。

------

# 23. Window Resize

必须处理：

```text
Android 横竖屏
iPad 分屏
折叠屏
Windows Resize
macOS Resize
```

屏幕尺寸变化：

```text
recalculate availableRect
↓
Clamp position
↓
Clamp size
```

保证窗口不会留在屏幕外。

# 24. Position 记忆

支持：

```dart
rememberPosition
```

第一阶段只要求当前 App 生命周期内记忆。

例如：

```text
video
→ 上次在右侧中间

下次打开视频浮窗
→ 可以继续使用对应位置
```

暂时不要写数据库。

以后需要再扩展持久化。

# 25. 视频业务架构

视频播放生命周期不能交给 FloatingWindow。

推荐：

```text
VideoPlaybackSession
│
├── controller
├── mediaId
├── url/source
├── duration
├── position
├── playing
├── volume
└── metadata
```

页面结构：

```text
VideoPlaybackSession
       │
  ┌────┴───────────┐
  ↓                ↓
FullVideoView   FloatingVideoContent
```

要求：

> Full → Floating → Full 过程中不要重新创建播放 Session。

# 27. 视频浮窗示例

```dart
floatingWindowManager.show(
  id: 'video:$mediaId',
  type: FloatingWindowType.video,
  contentMode: FloatingWindowContentMode.flutter,
  options: FloatingWindowOptions.video(),
  child: VideoFloatingContent(
    session: playbackSession,
  ),
);
```

点击恢复：

```text
FloatingVideo
↓
重新打开 VideoPlayerPage
↓
传入原 VideoPlaybackSession
↓
隐藏/关闭 FloatingWindow
```

例如：

```text
00:35 缩小
↓
小窗继续播放
↓
00:52 点击恢复
↓
继续从 00:52 播放
```

不能从头重新播放。

------

# 28. 不要强制把 Video Surface 做 Hero

一些播放器底层使用：

```text
Texture
PlatformView
Native Surface
```

如果直接 Hero 可能：

- 黑屏
- 闪帧
- Surface 重建
- Controller 生命周期异常

推荐：

```text
Hero
↓
封面 / 当前帧
↓
转场完成
↓
显示真实播放器
```

实际播放器经过各平台人工验证稳定后，再考虑直接做 Hero。

# 29. WebView 支持

FloatingWindow 必须支持承载 WebView。

典型：

```text
Workbench WebView
↓
点击悬浮
↓
WebView FloatingWindow
↓
继续聊天
↓
点击恢复
↓
继续原来的 H5 页面
```

WebView 业务组件例如：

```text
WebViewFloatingContent
```

属于 WebView / Workbench 业务模块。

不要放到 FloatingWindow Core 中。

# 30. WebView Session

建议 WebView 业务层存在统一 Session。

例如：

```dart
class WebViewSession {
  final String id;

  final WebViewController controller;

  Uri? currentUri;

  String? title;

  bool canGoBack;

  bool canGoForward;

  bool loading;
}
```

实际字段根据现有项目 WebView 封装调整。

FloatingWindow 不感知这些字段。

# 31. WebView 状态保持

目标：

```text
H5 已经进入内部页面
↓
已经登录
↓
已经滚动
↓
已经输入部分内容
↓
缩成 FloatingWindow
↓
尽量保持原状态
```

不能简单：

```text
缩小
↓
重新 new WebView
↓
重新 loadUrl(home)
```

必须优先复用项目已有：

```text
WebViewController
Session
Cookie
Navigation State
```

------

# 32. WebView PlatformView 生命周期注意事项

不要假定所有 WebView 插件、所有平台都能：

```text
把同一个原生 WebView Widget 实例直接从页面 Tree 移动到 FloatingWindow Tree
```

Codex 必须根据当前项目实际使用的 WebView 插件测试。

优先策略：

### 方案 A

插件支持安全复用 Controller：

```text
保持 WebViewSession / Controller
↓
切换显示 Host
```

### 方案 B

如果 PlatformView 在 reparent 时会重建或异常：

```text
保持 WebView 实际 Host 稳定
↓
通过统一 Container / Offstage / Indexed host 管理
↓
页面与浮窗只切换呈现状态
```

不要为了实现浮窗频繁销毁 Native WebView。

必须人工验证：

```text
Android
iOS
Windows
macOS
```

Web 平台也要检查对应实现。

# 33. WebView Header

WebView FloatingWindow 推荐：

```text
┌─────────────────────────────┐
│ ≡  当前网页标题         □ × │
├─────────────────────────────┤
│                             │
│           WebView           │
│                             │
└─────────────────────────────┘
```

Header：

- Drag
- Title
- Restore
- Close

WebView：

- 页面点击
- 页面滚动
- 页面输入
- JSBridge
- 网页内部导航

不要让 WebView 内容区域承担窗口拖动。

------

# 34. WebView 尺寸

默认建议：

```text
比视频浮窗更大
```

例如根据屏幕宽度动态计算。

不要写死绝对尺寸。

配置：

```dart
FloatingWindowOptions.webView()
```

桌面端允许 Resize。

手机端可以默认固定宽高范围。

```text
↓
点击 HTML input
↓
Keyboard 打开
↓
FloatingWindow 仍然保持在合法区域
```

同时不能破坏：

```text

焦点
```

------

# 36. WebView Z-Order

PlatformView 在不同平台可能存在：

```text
z-order
Overlay
Clip
Pointer
Composition
```

限制。

Codex 必须测试 FloatingWindow 上的：

```text
关闭按钮
标题栏
恢复按钮
Resize Handle
```

是否能够正常覆盖在 WebView 上。

如果某个平台不能稳定覆盖：

优先调整结构，例如：

```text
Header 独立于 WebView PlatformView
```

不要依赖复杂半透明 Overlay 覆盖整个 WebView。

# 38. WebView 插件解耦

FloatingWindow Core 禁止：

```dart
import 'package:webview_flutter/...';
```

也禁止：

```dart
import 'package:flutter_inappwebview/...';
```

正确：

```text
FloatingWindow
        ↓
Widget child
        ↓
WebViewFloatingContent
        ↓
项目 WebView abstraction
        ↓
具体 WebView 插件
```

将来替换：

```text
webview_flutter
flutter_inappwebview
WebView2
其他平台实现
```

FloatingWindow 不修改。

------

# 67. 验收标准

最终应该可以实现：

```dart
floatingWindowManager.show(
  id: 'xxx',
  child: anyWidget,
);
```

然后该 Widget：

```text
成为 App 内浮动窗口
↓
可以拖动
↓
可以吸边
↓
可以跨路由
↓
可以避免键盘
↓
可以响应 Window Resize
```

对于 WebView：

```text
H5 页面
↓
FloatingWindow
↓
页面尽量不 reload
↓
内部滚动/点击正常
↓
Header 拖动正常
↓
恢复后继续原页面
```

对于视频：

```text
聊天缩略图
↓ Hero
播放器
↓ FloatingWindow
小窗继续播放
↓
恢复
↓
继续原播放位置
```

最终原则：

> Hero 负责转场。

> FloatingWindow 负责持续存在。

> Session 负责业务生命周期。

> PlatformView 由业务层适配，FloatingWindow Core 不依赖具体插件。
