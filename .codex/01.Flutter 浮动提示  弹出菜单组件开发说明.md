# Flutter 浮动提示 / 弹出菜单组件开发说明

## 一、目标

为当前 Flutter 项目封装一套通用的浮动提示组件，用于：

- 聊天消息长按菜单
- 右键菜单
- 表情快捷操作
- 用户信息预览
- 文件操作菜单
- 工具提示
- 自定义浮动内容
- 其他需要依附某个 Widget 显示的浮层

核心组件必须保持通用，**不能直接绑定聊天消息业务**。

聊天消息菜单只是该组件的一个业务使用场景。

------

# 二、总体设计

建议分两层。

```text
FloatingPopover
    ↓
通用浮层基础能力

ChatMessageMenu
    ↓
聊天消息菜单业务能力
```

职责必须分开。

------

# 三、FloatingPopover

## 3.1 定位

建议基于 Flutter 原生能力实现：

- `Overlay`
- `OverlayEntry`
- `LayerLink`
- `CompositedTransformTarget`
- `CompositedTransformFollower`

不要简单封装 `showMenu()`。

原因：

- 聊天列表会滚动
- 消息高度不固定
- 消息可能靠近屏幕边缘
- 桌面端存在窗口尺寸变化
- Web / Windows / macOS 需要右键菜单
- 后续需要支持表情菜单、自定义工具栏等复杂内容

------

# 四、FloatingPopover 能力要求

基础组件至少支持以下能力。

## 显示方向

支持：

```dart
enum FloatingPlacement {
  auto,
  top,
  bottom,
  left,
  right,
  topStart,
  topEnd,
  bottomStart,
  bottomEnd,
}
```

默认：

```dart
FloatingPlacement.auto
```

`auto` 模式需要根据目标 Widget 与当前可视区域自动选择合适的位置。

不能写死始终显示在顶部或底部。

------

## 边界处理

必须考虑：

- 屏幕顶部
- 屏幕底部
- 屏幕左右边缘
- SafeArea
- 键盘弹起
- 桌面窗口尺寸变化
- Web 浏览器窗口变化

Popover 不允许超出当前有效显示区域。

必要时：

```text
top → bottom
bottom → top
left → right
right → left
```

自动翻转。

------

## 跟随目标

Popover 显示后：

- 聊天列表滚动
- 页面滚动
- 窗口变化

浮层应该尽可能继续跟随目标 Widget。

如果目标 Widget 已经离开 Widget Tree，则自动关闭浮层。

------

## 关闭行为

支持配置：

```dart
dismissOnTapOutside
dismissOnEscape
dismissOnScroll
dismissOnRouteChanged
```

默认建议：

```dart
dismissOnTapOutside = true
dismissOnEscape = true
```

聊天消息场景是否滚动关闭，由业务配置决定。

------

## 展示方式

需要支持：

```dart
controller.show();
controller.hide();
controller.toggle();
```

同时支持事件触发。

移动端：

```text
LongPress
Tap
```

桌面 / Web：

```text
SecondaryTap
RightClick
```

基础组件不要强制某一种手势。

------

# 五、Controller

提供统一 Controller：

```dart
class FloatingPopoverController {
  void show();
  void hide();
  void toggle();

  bool get isVisible;
}
```

后续如有需要可以扩展：

```dart
showAt(...)
showWithContext(...)
update()
```

不要让业务代码直接操作 `OverlayEntry`。

------

# 六、组件建议 API

API 可以根据现有项目规范调整，不要求完全照搬下面定义。

参考：

```dart
FloatingPopover(
  controller: controller,

  placement: FloatingPlacement.auto,

  offset: const Offset(0, 8),

  dismissOnTapOutside: true,

  child: targetWidget,

  contentBuilder: (context) {
    return popoverContent;
  },
);
```

核心要求：

```text
child
```

代表被依附的目标。

```text
contentBuilder
```

允许传入任意 Widget。

因此 FloatingPopover 本身：

**禁止知道 ChatMessage、MessageType、User、Session 等业务模型。**

------

# 七、样式

支持统一 Theme，同时允许局部覆盖。

建议：

```dart
FloatingPopoverTheme
```

至少考虑：

- backgroundColor
- borderRadius
- border
- boxShadow
- padding
- margin
- maxWidth
- maxHeight
- animationDuration
- animationCurve
- arrow
- arrowSize
- arrowOffset
- blur

可以与当前 App Theme：

```dart
ThemeData
ColorScheme
```

结合。

需要同时兼容：

- Light
- Dark

避免在业务组件内写死颜色。

# 八、箭头

Popover 可以支持可选箭头。

例如：

```text
┌────────────────────┐
│ 回复 复制 转发 ... │
└─────────┬──────────┘
          ▼
       消息气泡
```

支持：

```dart
showArrow
arrowSize
arrowOffset
```

箭头位置需要跟随：

```dart
FloatingPlacement
```

变化。

箭头不是所有菜单都必须显示，因此必须可以关闭。

------

# 九、动画

默认提供简单动画：

- Fade
- Scale

例如：

```text
Opacity:
0 → 1

Scale:
0.95 → 1
```

不要做复杂动画。

动画时长建议：

```text
120ms ~ 180ms
```

但必须通过 Theme 或参数配置。

# 十、聊天消息菜单

聊天消息菜单放在聊天模块中实现。

例如：

```text
features/chat/
  presentation/
    widgets/
      message_menu/
```

具体目录根据当前项目结构调整。

建议：

```text
chat_message_menu.dart
chat_message_menu_item.dart
chat_message_menu_builder.dart
chat_message_menu_context.dart
```

重点：

**不要直接在 ChatMessageMenu Widget 中写死所有菜单。**

------

# 十一、聊天菜单为什么不能写死

不同消息可能显示完全不同的操作。

例如：

```text
文本消息
图片消息
视频消息
语音消息
文件消息
位置消息
名片消息
系统消息
撤回消息
失败消息
正在发送消息
机器人消息
```

菜单也和状态相关。

例如：

```text
是否自己发送
是否发送成功
是否发送失败
是否撤回
是否已经删除
是否允许撤回
是否允许删除
是否允许编辑
是否允许复制
是否允许下载
是否已经下载
是否收藏
是否允许转发
是否允许引用
是否为系统消息
```

因此：

**UI 只能负责渲染菜单。**

菜单内容必须通过业务层动态生成。

建议定义菜单上下文。

参考：

```dart
class ChatMessageMenuContext {

  final bool canRecall;

  final bool canDelete;

  final bool canForward;

  final bool canReply;

  final bool canCopy;

  final bool canDownload;

  final bool canEdit;

  final bool canFavorite;

  // 根据当前项目实际状态继续扩展
}
```

注意：

这里仅作为设计示意。

Codex 应优先复用当前项目：

```text
Message Entity
Message DTO
MessageType
MessageState
SessionUnit
当前登录身份
权限体系
```

不要重新创建一套重复的数据模型。

# 十三、ChatMessageMenuItem

菜单使用配置模型描述。

参考：

```dart
class ChatMessageMenuItem {
  final String id;

  final String label;

  final IconData? icon;

  final bool enabled;

  final bool destructive;

  final FutureOr<void> Function()? onTap;
}
```

也可以支持：

```dart
Widget? iconWidget
WidgetBuilder?
```

具体结合当前 UI 基础设施调整。

菜单项必须存在稳定的：

```text
id
```

例如：

```text
reply
copy
forward
download
save
favorite
edit
recall
delete
multiSelect
```

业务判断尽量使用 id，而不是菜单中文名称。

------

# 十四、菜单生成器

建议单独做：

```dart
ChatMessageMenuBuilder
```

或者：

```dart
ChatMessageMenuResolver
```

职责：

根据当前消息上下文动态生成菜单。

例如：

```dart
final items = menuBuilder.build(
  message: message,
  context: menuContext,
);
```

返回：

```dart
List<ChatMessageMenuItem>
```

------

# 十五、菜单动态规则

禁止类似：

```dart
if (message.type == text) {
  return [
    copy,
    reply,
    delete,
  ];
}
```

全部堆积在 Widget 的 `build()` 中。

业务规则应该集中管理。

例如可以采用：

```text
基础菜单
+
消息类型菜单
+
消息状态菜单
+
发送方菜单
+
权限菜单
```

最终合并、过滤。

# 十六、规则示例

下面仅用于说明设计思想，具体规则必须根据当前项目已有 Message 类型和状态实现。

## 普通文本

可能包含：

```text

复制
转发
收藏
多选
```

自己发送还可能：

```text
撤回
编辑
删除
```

------

## 图片

可能包含：

```text
回复
转发
保存图片
收藏
多选
删除
```

不能出现：

```text
复制文本
```

除非项目以后增加 OCR 能力。

------

## 视频

可能包含：

```text
回复
转发
保存视频
收藏
多选
删除
```

------

## 文件

可能包含：

```text
打开
下载
另存为
转发
收藏
删除
```

------

## 语音

可能包含：

```text
播放
转文字
回复
转发
收藏
删除
```

是否支持“转文字”取决于项目功能。

------

## 发送失败

可能优先显示：

```text
重新发送
删除
```

部分普通菜单需要隐藏。

------

## 发送中

可能：

```text
取消发送
```

或者完全不显示菜单。

根据当前项目实际实现。

------

## 已撤回

一般不要显示普通消息菜单。

如果项目存在：

```text
重新编辑
删除
```

则由业务规则决定。

------

# 十七、不要只根据 MessageType

菜单规则不能只判断：

```dart
message.type
```

至少应该综合考虑：

```text
MessageType
MessageState
发送方
当前身份
权限
消息内容
消息时间
会话类型
文件本地状态
平台能力
```

例如：

```text
撤回
```

可能不仅要求：

```text
isSelf == true
```

还需要判断：

```text
消息发送成功
+
没有撤回
+
在允许撤回时间范围内
+
当前身份有权限
```

这类规则应放在业务层，而不是 UI。

------

# 十八、建议支持 Provider 机制

为了避免后续消息类型越来越多，可以进一步支持：

```dart
abstract interface class ChatMessageMenuProvider {
  bool supports(...);

  List<ChatMessageMenuItem> build(...);
}
```

例如：

```text
CommonMessageMenuProvider

TextMessageMenuProvider

ImageMessageMenuProvider

VideoMessageMenuProvider

FileMessageMenuProvider

FailedMessageMenuProvider
```

但不要为了架构而过度抽象。

如果当前消息类型较少，可以先使用一个：

```text
ChatMessageMenuBuilder
```

集中实现。

后续复杂后再拆 Provider。

`ChatMessageMenu` 只接收：

```dart
List<ChatMessageMenuItem>
```

例如：

```dart
ChatMessageMenu(
  items: items,
);
```

它不负责判断：

```text
是不是自己发送
是不是发送失败
```

# 二十、支持多种菜单布局

同一套菜单数据最好可以渲染成不同布局。

例如：

## 横向菜单 可以设置一行最多项，自动换行。

```text
┌─────────────────────────────┐
│ 回复  复制  转发  收藏  ••• │
└─────────────────────────────┘
```

适合聊天常用操作。

------

## 纵向菜单

```text
┌────────────┐
│ 回复       │
│ 复制       │
│ 转发       │
│ 收藏       │
├────────────┤
│ 删除       │
└────────────┘
```

适合桌面端右键菜单或者更多操作。

因此建议：

```text
菜单数据
```

和：

```text
菜单 UI
```

分离。

------

# 二十一、更多菜单

当菜单数量较多时，例如：

```text
回复
复制
转发
收藏
编辑
撤回
多选
翻译
删除
```

不要全部横向排列。

建议支持：

```text
常用操作 + 更多
```

例如：

```text
回复
复制
转发
收藏
•••
```

点击：

```text
•••
```

显示完整纵向菜单。

具体最大显示数量可配置。

不要写死 4 个或者 5 个。

------

# 二十二、移动端交互

聊天消息：


打开菜单。

如果后续已经存在：

```text
消息选择
滑动回复
双击
```

需要注意手势冲突。

# 二十三、Windows / macOS / Web

桌面端需要支持：

```text
右键
```

例如：

```dart
onSecondaryTap
```

或：

```dart
onSecondaryTapDown
```

右键菜单最好能够在鼠标位置附近弹出。

因此 FloatingPopover 后续最好支持两种定位模式：

```text

```

例如：


```dart

```

如果第一版工作量较大，可以先实现 Anchor Widget，结构上保留扩展空间。

不要在 UI 内直接：

具体沿用当前项目已有架构。

# 二十五、菜单显示和菜单执行必须分离

例如：

```text
是否显示“撤回”
```

属于：

```text
Menu Rule
```

而：

```text

```

属于：

```text

```

不要混在一起。

# 二十六、使用方式

业务代码期望类似：

```dart
final menuItems = menuBuilder.build(
  message: message,
  sessionUnit: sessionUnit,
  currentIdentity: currentIdentity,
);

return FloatingPopover(
  controller: popoverController,

  placement: FloatingPlacement.auto,

  child: MessageBubble(
    message: message,
  ),

  contentBuilder: (_) {
    return ChatMessageMenu(
      items: menuItems,
    );
  },
);
```

实际 API 根据当前项目结构调整。

------

# 二十七、避免每条消息创建复杂对象

聊天列表可能同时存在大量消息。

注意性能：

不要为每条消息长期创建：

```text
OverlayEntry
AnimationController
FocusNode
GlobalKey
```

除非确实需要。

Popover 未打开时尽量保持轻量。

只有打开菜单时才创建真正的 Overlay 内容。

------

# 二十八、聊天虚拟列表兼容

当前项目聊天列表属于高频滚动、非固定高度消息场景。

实现时必须验证：

- 快速滚动
- prepend 历史消息
- append 新消息
- reverse list
- 消息高度变化
- 图片加载后高度变化
- 消息被删除
- 消息撤回
- target Widget 被回收

目标消息被回收后：

```text
Popover 自动关闭
```

不能残留在屏幕上。

------

# 二十九、与聊天气泡解耦

不要把 FloatingPopover 写进：

```text
TextMessageBubble
ImageMessageBubble
VideoMessageBubble
```

每一个消息组件。

建议在统一消息 Item 层处理：

```text
ChatMessageItem
    ├── FloatingPopover
    └── MessageBubble
          ├── TextBubble
          ├── ImageBubble
          ├── VideoBubble
          ├── VoiceBubble
          └── FileBubble
```

这样菜单行为统一。

------

# 三十、菜单关闭

执行菜单操作后默认关闭。

建议：

```dart
await action();

popoverController.hide();
```

对于某些操作：

```text
表情选择
二级菜单
多选模式
```

可以允许业务控制是否立即关闭。

不要在 `ChatMessageMenu` 中强制所有 item 点击后关闭。

# 三十五、代码原则

遵循当前 Flutter 项目的整体规范。

重点：

1. 不过度设计。
2. 不重复建立已有模型。
3. 优先复用现有 Message、SessionUnit、身份、权限相关代码。
4. UI 和业务规则分离。
5. FloatingPopover 不依赖 Chat 模块。
6. ChatMessageMenu 可以依赖 FloatingPopover。
7. 菜单不能写死。
8. 菜单显示条件集中维护。
9. 菜单执行逻辑复用现有 Message Action。
10. Android、iOS、Web、Windows、macOS 均需考虑。

# 三十八、最终效果

理想调用关系：

```text
ChatMessageItem
      │
      ├─ Message
      │
      ▼
ChatMessageMenuBuilder
      │
      ▼
List<ChatMessageMenuItem>
      │
      ▼
ChatMessageMenu
      │
      ▼
FloatingPopover
      │
      ▼
Overlay
```

其中：

```text
FloatingPopover
```

只解决：

```text
显示在哪里
怎么显示
怎么关闭
怎么避免越界
ChatMessageMenuBuilder
```

只解决：

```text
当前消息应该有哪些菜单
Message Action
```

只解决：

```text
点击菜单以后执行什么
```

三者必须解耦。

# 三十九、Codex 执行要求

开始开发前先检查当前项目：

```text
消息模型
消息类型定义
消息状态定义
聊天 Message Item
消息气泡结构
当前身份获取方式
权限体系
Theme
开发诊断中心
```

基于现有代码适配，不要按照本文示例重新创建重复架构。

如果项目已有类似：

```text
Overlay
Popover
ContextMenu
MenuAction
```

先判断是否可以扩展，而不是重复实现。

完成以后：

1. 给出新增 / 修改文件。
2. 说明核心设计。
3. 给出聊天消息接入示例。
4. 给出新增消息类型如何扩展菜单的示例。
5. 给出新增菜单项如何增加的示例。
6. 给出各平台人工测试步骤。
7. 在开发诊断中心加入完整演示。
